# 115-cloud-load.js 返回说明

本文描述当前脚本的实际行为。脚本没有统一的成功或失败 JSON 输出，也没有导出可直接调用的函数；运行时通过日志和进程退出码表示结果。

## 一、脚本成功时

| 项目 | 返回或输出 |
| --- | --- |
| `main()`、`runCloudDownload()` 返回值 | Promise 正常完成，结果为 `undefined` |
| 标准输出（stdout） | 执行步骤日志，格式为 `[步骤 NNN] 消息`，附加数据以 ` | ` 分隔 |
| 进程退出码 | 正常结束时为 `0` |
| 最终结果 JSON | 不输出 |

主流程成功结束时会输出以下日志，步骤编号取决于实际执行路径：

```text
[步骤 NNN] 完整的 115 自动化流程调用结束
[步骤 NNN] 正在关闭命令行交互接口
```

退出码 `0` 表示主流程没有抛出异常，不保证每个可选阶段都已执行：

- 没有磁力链接时，跳过云下载流程，也可以正常结束。
- 缺少 JSON 数据或任务名称时，跳过目录整理；缺少标题时，找到下载对象后跳过后续整理。
- 命中可复用的已完成下载时，直接整理该对象，不创建新任务，也就没有创建任务接口的响应。
- 浏览器与 Cookie 同步独立运行，失败仅写步骤日志，不设置主流程退出码。两条流程的日志可能交错。

## 二、脚本失败时

| 项目 | 返回或输出 |
| --- | --- |
| `main()`、`runCloudDownload()` 返回值 | Promise 被拒绝，错误通常为 `FlowError` |
| 标准输出（stdout） | 失败前的步骤日志及部分失败处理日志 |
| 标准错误（stderr） | `[错误码 <code>] <message>` |
| 进程退出码 | 最外层错误处理设置为 `flowError.code` |
| 最终结果 JSON | 不输出 |

例如，云下载任务接口返回失败状态时，标准错误可能是：

```text
[错误码 40] 云下载任务创建失败: 接口返回失败状态
```

此时脚本设置退出码为 `40`。错误消息会随实际接口响应变化。

`FlowError` 包含 `name: 'FlowError'`、数字 `code` 和字符串 `message`；部分错误还带有 `cause`。这些是内部错误对象属性，脚本不会将整个错误对象序列化成 JSON 输出。

### 主流程错误码

| 错误码 | 含义 |
| --- | --- |
| `12` | 未知命令行参数 |
| `13` | 磁力链接格式或解码错误；目录清理阶段无法识别番号格式 |
| `14` | `--jav-json` 内容无法解析为 JSON |
| `15` | JSON 顶层不是对象 |
| `16` | JSON 缺少非空字符串 `code` |
| `17` | JSON 的 `code` 与指定番号不匹配 |
| `21` | API 响应不是有效 JSON，或已完成任务列表格式无效 |
| `22` | API 返回非 2xx HTTP 状态 |
| `23` | API 请求超时 |
| `24` | 无法访问本机 API |
| `40` | 云下载任务创建失败 |
| `41` | 任务完成确认超过 10 分钟 |
| `50` | 文件列表接口失败或格式无效 |
| `51` | 删除目录内文件失败 |
| `52` | 重试后仍未找到下载对象 |
| `53` | 下载对象缺少可用的 `fid` 或 `cid` |
| `54` | 重命名失败 |
| `55` | 目录整理阶段的非 `FlowError` 异常 |
| `56` | 删除云下载任务记录失败 |
| `99` | 未处理异常或通知广播失败 |

`asFlowError()` 会保留已有 `FlowError` 的错误码。例如，创建任务时 API 无法连接，最终退出码可为 `24`，不会强制改成 `40`；目录整理失败也可能保留 `51`、`52`、`54` 等具体错误码。

已完成下载检查失败会记录日志并回退到创建任务，因此该检查失败本身不一定导致脚本失败。任务创建失败后的删除记录失败，以及失败分支中的广播失败，只记录日志，保留原来的主流程错误。

## 三、内部创建任务函数返回什么

`addCloudTask(cloudLoadUrl)` 请求：

```text
POST http://127.0.0.1:1150/115/clouddownload/add_task_urls
```

请求体为：

```json
{
  "url": ["magnet:?xt=urn:btih:..."]
}
```

该函数返回 API 的完整解析响应，并以“云下载接口响应”步骤日志输出；主流程只取 `data[0]` 继续处理。这不是脚本最终返回的 JSON。

### 创建成功响应示例

```json
{
  "state": true,
  "errno": 0,
  "errcode": 0,
  "data": [
    {
      "state": true,
      "errno": 0,
      "errtype": "",
      "errcode": 0,
      "info_hash": "...",
      "name": "SAVR-1029.8K",
      "url": "magnet:?xt=urn:btih:..."
    }
  ]
}
```

主流程认定创建成功须同时满足：

- 顶层 `state === true`。
- `Number(errcode ?? errno ?? 0) === 0`。
- `data[0].state === true`。

`info_hash` 用于删除本次云下载任务记录，`name` 用于查找下载对象，`url` 是任务磁力链接。创建成功后，目录查找、重命名、通知或清理仍可能失败，最终结果需结合进程退出码判断。

创建成功后，脚本每隔 2 秒查询一次已完成任务（`/115/task_lists?stat=11`），不分页。匹配时使用 `info_hash` 或磁力链接的 BTIH，避免 `dn`、参数顺序和编码差异造成漏匹配；缺少哈希时才比较完整 URL。任务完成状态只检查 `status === 2`，并要求非空 `file_id`。找到任务后仅请求一次对应目录内容，校验通过才继续整理。

完成确认总时限为 10 分钟，任务查询和目录请求均受剩余时间约束。未匹配到任务时会输出任务哈希、已完成任务数量和剩余秒数，便于区分等待任务与请求未返回。

### 创建失败响应

若请求返回可解析的 JSON 且 HTTP 状态为 2xx，`addCloudTask()` 仍返回原始响应；不满足上述成功条件时，由主流程抛出错误码 `40`。

失败响应的字段由 API 决定，没有脚本统一包装的失败 JSON。最终错误消息优先取顶层 `error_msg`，其次取顶层 `message`，都没有时使用“接口返回失败状态”。

若请求本身失败，例如超时、无法连接、HTTP 非 2xx 或 JSON 解析失败，则 `addCloudTask()` 抛出异常，没有正常返回值。未提供磁力链接时，该函数直接返回，Promise 结果为 `undefined`。

## 四、成功和失败通知

脚本还会向 `/115/clouddownload/notify` 发送事件。这些是 HTTP 通知请求体，不是命令行返回值。

| `type` | 成功时 | 失败时 |
| --- | --- | --- |
| `cloud_download_found` | 找到有效下载对象后，`result: 0`、`message: ''` | 创建任务失败、未找到对象或对象 ID 缺失时，`result` 为相应错误码，`message` 为原因 |
| `cloud_download_renamed` | 实际重命名成功后，`result: 0`、`message: ''` | 重命名抛出异常时，`result` 为错误码，`message` 为原因 |

找到对象的通知 `data` 包含 `code`、`name`、`cid`、`info_hash`；重命名通知还包含 `from_name`。失败时部分字段为空字符串。普通文件的 `cid` 按对象实际提供的字段填写，不会改填 `fid`。

名称已是目标标题时，不发送重命名成功通知。参数校验失败等早期错误也不会发送上述事件；脚本没有统一的“全部流程成功”或“全部流程失败”通知。找到对象或重命名成功的通知发出后，后续步骤仍可能失败。
